# SeckillCore 用户模块需求文档

> **文档版本**：V2.0
> **所属项目**：SeckillCore 高并发秒杀系统
> **模块名称**：用户模块（User Module）
> **目标读者**：产品经理、后端开发、前端开发、测试工程师
> **变更记录**：V2.0 — 增强企业级安全规范，补充非功能需求


## 1. 模块概述

### 1.1 模块定位

用户模块是 SeckillCore 系统的基础支撑模块，负责**用户身份管理、认证授权、账户安全**等核心能力。所有业务模块（秒杀、订单、活动）均依赖用户模块提供的身份认证与用户信息查询服务。

### 1.2 业务目标

| 序号 | 目标 | 说明 |
| :---: | :--- | :--- |
| 1 | **统一身份认证** | 提供安全的登录/注册机制，支持 JWT 令牌认证 + Token 刷新 |
| 2 | **用户信息管理** | 支持用户基本信息的查询与修改 |
| 3 | **账户安全** | 支持密码加密存储、账户冻结/解冻、登录审计日志、密码历史限制 |
| 4 | **高并发支撑** | 登录接口需支撑峰值 5 万 QPS 的认证请求 |
| 5 | **服务内聚** | 用户信息通过 Feign 接口供其他微服务调用，避免各服务重复查询数据库 |

### 1.3 用户角色

| 角色 | 说明 |
| :--- | :--- |
| **普通用户（C端）** | 注册、登录、查看/修改个人信息 |
| **管理员（后台）** | 查看用户列表、冻结/解冻用户（由管理端 Web 调用） |
| **内部服务** | 通过 Feign 接口获取用户信息（需携带内部服务 Token 进行服务间认证） |

### 1.4 模块边界

| 包含内容 | 不包含内容 |
| :--- | :--- |
| 用户注册、登录、登出 | 用户权限管理（RBAC）—— 由独立权限模块负责 |
| JWT 令牌生成与验证 + Token 刷新 | 第三方登录（微信/支付宝） —— 二期规划 |
| 用户信息查询与修改 | 消息通知（短信/邮件） —— 由通知模块负责 |
| 用户状态管理（冻结/解冻） | 用户积分/等级 —— 由会员模块负责 |
| 登录审计日志 | 支付密码 —— 由支付模块负责 |


## 2. 功能需求

### 2.1 用户注册

| 项目 | 说明 |
| :--- | :--- |
| **功能编号** | UC-001 |
| **功能名称** | 用户注册 |
| **触发条件** | 用户访问注册页面并提交注册信息 |
| **前置条件** | 无 |
| **后置条件** | 系统创建用户账户，返回注册成功信息 |

**输入字段：**

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
| :--- | :--- | :---: | :--- | :--- |
| `username` | String | ✅ | 4-20位字母/数字/下划线，唯一，禁止 SQL/HTML 特殊字符 | 登录用户名 |
| `password` | String | ✅ | 8-20位，必须包含大写字母、小写字母、数字、特殊字符各至少1个 | 登录密码 |
| `confirmPassword` | String | ✅ | 必须与 password 一致 | 确认密码 |
| `phone` | String | ✅ | 11位中国大陆手机号，唯一 | 手机号 |
| `email` | String | ❌ | 标准邮箱格式（RFC 5322） | 邮箱（选填） |

**业务规则：**

1. 用户名全局唯一，重复则返回错误提示
2. 手机号全局唯一，重复则返回错误提示
3. 密码使用 BCrypt 加密存储（强度系数 10），不存储明文
4. 注册成功后自动生成雪花 ID 作为用户ID
5. 新用户默认状态为「正常」（status = 1）
6. 用户名需进行 XSS 过滤（过滤 `<` `>` `"` `'` `&` 等字符）
7. 同一 IP 每分钟最多注册 3 个账号（防批量注册）

**异常场景：**

| 异常场景 | 业务错误码 | HTTP状态码 | 错误信息 |
| :--- | :---: | :---: | :--- |
| 用户名为空 | 40001 | 400 | 用户名不能为空 |
| 用户名包含非法字符 | 40002 | 400 | 用户名只能包含字母、数字和下划线 |
| 用户名已存在 | 40901 | 409 | 用户名已被占用 |
| 手机号已注册 | 40902 | 409 | 手机号已被注册 |
| 密码强度不足 | 40003 | 400 | 密码需包含大写字母、小写字母、数字和特殊字符 |
| 两次密码不一致 | 40004 | 400 | 两次密码输入不一致 |
| 手机号格式错误 | 40005 | 400 | 手机号格式不正确 |
| 注册频率过高 | 42901 | 429 | 注册过于频繁，请稍后再试 |


### 2.2 用户登录

| 项目 | 说明 |
| :--- | :--- |
| **功能编号** | UC-002 |
| **功能名称** | 用户登录 |
| **触发条件** | 用户在登录页输入凭证并提交 |
| **前置条件** | 用户已注册 |
| **后置条件** | 系统签发 JWT 访问令牌 + 刷新令牌，记录登录审计日志 |

**输入字段：**

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
| :--- | :--- | :---: | :--- | :--- |
| `usernameOrPhone` | String | ✅ | 已存在的用户名或手机号 | 支持用户名或手机号登录 |
| `password` | String | ✅ | 正确的密码 | 登录密码 |

**响应信息：**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `token` | String | JWT 访问令牌（有效期 2 小时） |
| `refreshToken` | String | JWT 刷新令牌（有效期 7 天，仅用于续期访问令牌） |
| `userId` | Long | 用户ID |
| `username` | String | 用户名 |
| `avatar` | String | 头像URL |

**业务规则：**

1. 支持用户名/手机号两种登录方式（字段统一为 `usernameOrPhone`）
2. 密码校验使用 BCrypt 匹配
3. 登录成功后生成 JWT 访问令牌（有效期 2 小时）和刷新令牌（有效期 7 天）
4. 登录成功后记录登录时间、登录 IP、User-Agent 到审计日志
5. 同一登录凭证连续登录失败 5 次，锁定 15 分钟（防暴力破解）
6. 被冻结的用户无法登录
7. 同一账号最多允许 3 个设备同时在线（超出时踢出最早登录的设备）
8. 登录接口需做 IP 级别限流：单 IP 每秒最多 10 次请求

**异常场景：**

| 异常场景 | 业务错误码 | HTTP状态码 | 错误信息 |
| :--- | :---: | :---: | :--- |
| 凭证不存在 | 40101 | 401 | 用户名或密码错误 |
| 密码错误 | 40101 | 401 | 用户名或密码错误 |
| 账户已冻结 | 40301 | 403 | 账户已被冻结，请联系管理员 |
| 登录失败次数超限 | 42902 | 429 | 登录失败次数过多，请15分钟后再试 |
| 请求频率过高 | 42903 | 429 | 请求过于频繁，请稍后再试 |

> **安全说明**：用户名不存在和密码错误返回相同的错误码和错误信息，防止用户枚举攻击。


### 2.3 用户登出

| 项目 | 说明 |
| :--- | :--- |
| **功能编号** | UC-003 |
| **功能名称** | 用户登出 |
| **触发条件** | 用户点击登出按钮 |
| **前置条件** | 用户已登录 |
| **后置条件** | Token 加入黑名单，客户端清除 Token，刷新令牌同步失效 |

**业务规则：**

1. 将当前访问令牌加入 Redis 黑名单（有效期与 Token 剩余时间一致）
2. 清除该设备的刷新令牌（Redis 中 `refresh:token:{userId}:{deviceId}`）
3. 清除用户信息缓存（`user:info:{userId}`）
4. 记录登出审计日志（时间、IP、设备信息）
5. 客户端必须清除本地存储的 Token 和 refreshToken


### 2.4 Token 刷新

| 项目 | 说明 |
| :--- | :--- |
| **功能编号** | UC-009 |
| **功能名称** | Token 刷新 |
| **触发条件** | 访问令牌即将过期或已过期，客户端使用刷新令牌获取新令牌 |
| **前置条件** | 持有有效的刷新令牌 |
| **后置条件** | 返回新的访问令牌 + 新的刷新令牌（滚动刷新） |

**输入字段：**

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :---: | :--- |
| `refreshToken` | String | ✅ | 有效的刷新令牌 |

**响应信息：**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `token` | String | 新的 JWT 访问令牌 |
| `refreshToken` | String | 新的 JWT 刷新令牌（旧令牌同时失效） |

**业务规则：**

1. 刷新令牌有效期 7 天，过期后需重新登录
2. 采用滚动刷新策略：每次刷新同时下发新的刷新令牌，旧刷新令牌立即失效
3. 刷新令牌使用 Redis 存储，支持主动失效
4. 若刷新令牌已被盗用（检测到重复使用），立即失效该用户所有令牌并记录安全事件

**异常场景：**

| 异常场景 | 业务错误码 | HTTP状态码 | 错误信息 |
| :--- | :---: | :---: | :--- |
| 刷新令牌无效 | 40102 | 401 | 无效的刷新令牌 |
| 刷新令牌已过期 | 40103 | 401 | 登录已过期，请重新登录 |
| 刷新令牌已被使用 | 40104 | 401 | 令牌已被使用，请重新登录 |


### 2.5 获取当前用户信息

| 项目 | 说明 |
| :--- | :--- |
| **功能编号** | UC-004 |
| **功能名称** | 获取当前用户信息 |
| **触发条件** | 用户进入个人中心或需要获取用户信息 |
| **前置条件** | 用户已登录（请求头携带 Token） |
| **后置条件** | 返回用户详细信息 |

**响应信息：**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `userId` | Long | 用户ID |
| `username` | String | 用户名 |
| `phone` | String | 手机号（脱敏：138****1234） |
| `email` | String | 邮箱（脱敏：u***@example.com） |
| `avatar` | String | 头像URL |
| `status` | Integer | 状态：0冻结 / 1正常 |
| `lastLoginTime` | String | 最后登录时间 |

3. 手机号脱敏：保留前3后4，中间替换为 `****`
4. 邮箱脱敏：保留首字符和域名，中间替换为 `***`

| Token 无效 | 40106 | 401 | 无效的登录凭证 |
| Token 未提供 | 40107 | 401 | 请先登录 |
| 用户不存在 | 40401 | 404 | 用户不存在 |

### 2.7 修改密码

| 项目 | 说明 |
| :--- | :--- |
| **功能编号** | UC-006 |
| **功能名称** | 修改密码 |
| **触发条件** | 用户主动修改登录密码 |
| **前置条件** | 用户已登录 |
| **后置条件** | 密码修改成功，所有旧 Token 立即失效，需重新登录 |

**输入字段：**

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
| :--- | :--- | :---: | :--- | :--- |
| `oldPassword` | String | ✅ | 当前正确密码 | 旧密码 |
| `newPassword` | String | ✅ | 8-20位，必须包含大写字母、小写字母、数字、特殊字符各至少1个 | 新密码 |
| `confirmPassword` | String | ✅ | 必须与 newPassword 一致 | 确认新密码 |

**业务规则：**

1. 旧密码校验使用 BCrypt 匹配
2. 新密码不能与旧密码相同
3. 新密码不能与最近 3 次历史密码相同（密码历史记录保留最近 3 次哈希值）
4. 密码修改成功后，立即失效该用户所有 Token（访问令牌 + 刷新令牌）
5. 密码修改成功后，清除用户信息缓存
6. 若接入通知服务，密码修改成功后向用户邮箱/手机发送安全提醒

**异常场景：**

| 异常场景 | 业务错误码 | HTTP状态码 | 错误信息 |
| :--- | :---: | :---: | :--- |
| 旧密码错误 | 40108 | 401 | 旧密码输入错误 |
| 新旧密码相同 | 40008 | 400 | 新密码不能与旧密码相同 |
| 新密码与历史密码重复 | 40009 | 400 | 新密码不能与最近使用过的密码相同 |
| 新密码格式不符 | 40003 | 400 | 密码需包含大写字母、小写字母、数字和特殊字符 |


### 2.8 内部服务查询用户信息（Feign 接口）

| 项目 | 说明 |
| :--- | :--- |
| **功能编号** | UC-007 |
| **功能名称** | 内部查询用户信息 |
| **触发条件** | 其他微服务（订单/秒杀）需要获取用户信息 |
| **前置条件** | 调用方为注册的服务，携带内部服务认证 Token |
| **后置条件** | 返回用户核心信息 |

**输入参数：**

| 参数 | 类型 | 必填 | 说明 |
| :--- | :--- | :---: | :--- |
| `userId` | Long | ✅ | 用户ID |

**响应信息（内部 DTO）：**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `userId` | Long | 用户ID |
| `username` | String | 用户名 |
| `phone` | String | 手机号（脱敏） |
| `status` | Integer | 用户状态：0冻结 / 1正常 |

**业务规则：**

1. 仅限内部服务调用，不对外暴露（通过网关层屏蔽外部访问）
2. 调用方需携带内部服务认证 Token（`X-Internal-Token` 请求头），由 Gateway 或拦截器校验
3. 不包含密码等敏感信息
4. 优先从 Redis 缓存读取（key: `user:info:{userId}`），命中率目标 ≥ 95%
5. 若用户不存在，返回 null（调用方需自行处理空值）
6. 批量查询接口单次最多支持 100 个 userId

> **安全说明**：`/api/v1/internal/**` 路径在 Gateway 层配置为仅允许内网服务访问，外部请求直接拒绝。

| **前置条件** | 调用方具有管理员权限 |

3. 冻结后用户无法登录
4. 冻结后用户无法参与任何秒杀活动
5. 状态变更需记录操作审计日志（操作人ID、目标用户ID、操作类型、时间、IP）
6. 状态变更后清除用户信息缓存（`user:info:{userId}`）

## 3. 非功能需求

### 3.1 性能需求

| 指标 | 目标值 | 说明 |
| :--- | :---: | :--- |
| 注册接口响应时间 | < 500ms | 正常负载下（P99） |
| 登录接口响应时间 | < 200ms | 不含 BCrypt 加密计算耗时（P99） |
| 登录接口 QPS | ≥ 50,000 | 峰值流量 |
| 用户信息查询 QPS | ≥ 100,000 | 缓存命中率 ≥ 95% |
| Token 刷新接口响应时间 | < 50ms | 纯 Redis 操作 |
| 系统可用性 | 99.99% | 全年停机时间 < 53分钟 |

### 3.2 安全需求

| 需求项 | 说明 |
| :--- | :--- |
| 密码加密 | 使用 BCrypt 加密（强度系数 10，即 2^10 = 1024 轮哈希） |
| 密码强度 | 8-20位，必须包含大写字母、小写字母、数字、特殊字符各至少1个 |
| 密码历史 | 保留最近 3 次密码哈希值，禁止重复使用 |
| 传输安全 | 全链路 HTTPS（生产环境强制），HSTS 头设置 |
| 防暴力破解 | 连续 5 次登录失败锁定 15 分钟（基于登录凭证，非 IP） |
| 接口限流 | 登录接口：单 IP 10次/秒；注册接口：单 IP 3次/分钟 |
| 防重放攻击 | JWT 包含 `iat`（签发时间）、`exp`（过期时间）、`jti`（唯一ID） |
| 防 Session 伪造 | Token 包含 HMAC-SHA256 签名，服务端不保存 Session |
| SQL 注入防护 | 使用 MyBatis-Plus 参数绑定（LambdaQueryWrapper），禁止拼接 SQL |
| XSS 防护 | 所有用户输入进行 HTML 实体编码过滤，响应头设置 `X-XSS-Protection: 1; mode=block` |
| 敏感信息脱敏 | 手机号、邮箱在返回前端时脱敏；密码、Token 不出现在日志中 |
| 安全响应头 | `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Strict-Transport-Security` |
| 请求体限制 | 所有接口请求体最大 1MB（防止大 payload 攻击） |
| CORS 策略 | 仅允许白名单域名跨域访问，禁止 `Access-Control-Allow-Origin: *` |
| 服务间认证 | Feign 内部接口需携带 `X-Internal-Token` 请求头，Gateway 层校验 |

### 3.3 缓存策略

| 缓存对象 | 缓存方式 | 过期时间 | Key | 说明 |
| :--- | :--- | :---: | :--- | :--- |
| 用户信息（单条） | Redis String（JSON） | 30分钟 | `user:info:{userId}` | 查询时先查缓存，未命中查DB写缓存 |
| 访问令牌 | Redis String | 2小时 | `token:{userId}` | 登录时写入，登出/冻结时删除 |
| 刷新令牌 | Redis String | 7天 | `refresh:token:{userId}:{deviceId}` | 支持滚动刷新，多设备独立存储 |
| 登录失败计数 | Redis String | 15分钟 | `user:login:fail:{usernameOrPhone}` | 基于登录凭证计数 |
| Token 黑名单 | Redis String | Token剩余时间 | `token:blacklist:{token}` | 登出/冻结/密码修改时写入 |
| 接口限流计数 | Redis String | 滑动窗口 | `rate:limit:{api}:{ip}` | 基于 IP 的滑动窗口限流 |

**降级策略：**

| 场景 | 降级方案 |
| :--- | :--- |
| Redis 不可用 | 跳过缓存直接查数据库；限流降级为本地令牌桶；登出黑名单跳过 |
| Redis 恢复后 | 缓存自动重建（懒加载），无需人工干预 |

### 3.4 可观测性需求

| 需求项 | 说明 |
| :--- | :--- |
| 健康检查 | 提供 `/actuator/health` 端点，包含数据库和 Redis 连通性检查 |
| 指标监控 | 暴露 Prometheus 指标：接口 QPS、响应时间分位数（P50/P90/P99）、缓存命中率、错误率 |
| 分布式追踪 | 集成 Sleuth + Zipkin，每个请求携带 TraceId，跨服务追踪 |
| 审计日志 | 记录登录、登出、密码修改、状态变更事件，包含时间、IP、User-Agent、操作结果 |
| 告警规则 | 登录失败率 > 20%（5分钟内）触发告警；缓存命中率 < 90% 触发告警 |

### 3.5 扩展性需求

- 支持后续扩展第三方登录（微信、支付宝）
- 支持后续扩展手机号/邮箱验证码登录
- 支持后续扩展多因素认证（MFA/2FA）
- 用户信息表预留扩展字段（`ext_info` JSON 类型）
- 支持后续扩展账户注销（软删除）功能

### 3.6 数据保留策略

| 数据类型 | 保留周期 | 说明 |
| :--- | :--- | :--- |
| 用户账户数据 | 永久 | 账户注销后软删除（逻辑删除），数据保留 90 天后物理清除 |
| 登录审计日志 | 90天 | 保留最近 90 天，超期自动归档或删除 |
| 密码历史记录 | 永久（仅3条） | 仅保留最近 3 次密码哈希值 |
| Redis 缓存 | 按各自 TTL | 自动过期，无需手动清理 |

### 4.2 内部 Feign 接口

| 接口名称 | 方法 | 路径 | 说明 |
| :--- | :---: | :--- | :--- |
| 查询用户信息 | GET | `/api/v1/internal/users/{userId}` | 供其他微服务调用，需携带 `X-Internal-Token` |
| 批量查询用户 | POST | `/api/v1/internal/users/batch` | 批量查询，单次最多 100 个ID |

> **安全说明**：`/api/v1/internal/**` 路径在 Gateway 层配置为仅允许内网服务（注册中心来源）访问，外部请求直接返回 404。

### 4.3 接口数据格式

**统一响应格式：**

```json
{
    "code": 200,
    "msg": "success",
    "data": {
        "token": "eyJhbGciOiJIUzI1NiJ9...",
        "userId": 10001,
        "username": "zhangsan"
    },
    "timestamp": 1694339200000,
    "traceId": "a1b2c3d4e5f6"
}
```

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `code` | Integer | 业务状态码，200 表示成功 |
| `msg` | String | 提示信息 |
| `data` | Object | 响应数据，无数据时为 `null` |
| `timestamp` | Long | 响应时间戳（毫秒） |
| `traceId` | String | 分布式追踪ID，用于问题排查 |

**业务错误码规范：**

| 错误码范围 | 分类 | 说明 |
| :--- | :--- | :--- |
| 200 | 成功 | 操作成功 |
| 40001 - 40099 | 参数校验错误 | 请求参数不合法 |
| 40101 - 40199 | 认证错误 | 登录凭证无效、Token 过期等 |
| 40301 - 40399 | 授权错误 | 无权限访问、账户冻结等 |
| 40401 - 40499 | 资源不存在 | 用户不存在等 |
| 40901 - 40999 | 资源冲突 | 用户名/手机号已存在等 |
| 42901 - 42999 | 限流错误 | 请求频率过高 |
| 50001 - 50099 | 服务端错误 | 系统内部异常 |

### 4.4 请求头规范

| 请求头 | 类型 | 必填 | 说明 |
| :--- | :--- | :---: | :--- |
| `Authorization` | String | 条件 | 认证接口必填，格式：`Bearer <jwt_token>` |
| `Content-Type` | String | ✅ | 固定为 `application/json; charset=UTF-8` |
| `X-Request-Id` | String | ❌ | 客户端请求追踪ID，用于端到端排查 |
| `X-Internal-Token` | String | 内部接口 | Feign 内部服务认证 Token |
| `User-Agent` | String | ❌ | 用于审计日志记录设备信息 |

### 4.5 响应头规范

| 响应头 | 说明 |
| :--- | :--- |
| `X-Content-Type-Options` | `nosniff`（防止 MIME 类型嗅探） |
| `X-Frame-Options` | `DENY`（防止点击劫持） |
| `X-XSS-Protection` | `1; mode=block`（启用 XSS 过滤器） |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains`（强制 HTTPS） |
| `Cache-Control` | 按接口类型设置（敏感数据接口设为 `no-store`） |
