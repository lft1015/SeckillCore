# SeckillCore 用户模块需求文档

> **文档版本**：V1.0
> **所属项目**：SeckillCore 高并发秒杀系统
> **模块名称**：用户模块（User Module）
> **目标读者**：产品经理、后端开发、前端开发、测试工程师


## 1. 模块概述

### 1.1 模块定位

用户模块是 SeckillCore 系统的基础支撑模块，负责**用户身份管理、认证授权、账户安全**等核心能力。所有业务模块（秒杀、订单、活动）均依赖用户模块提供的身份认证与用户信息查询服务。

### 1.2 业务目标

| 序号 | 目标 | 说明 |
| :---: | :--- | :--- |
| 1 | **统一身份认证** | 提供安全的登录/注册机制，支持 JWT 令牌认证 |
| 2 | **用户信息管理** | 支持用户基本信息的查询与修改 |
| 3 | **账户安全** | 支持密码加密存储、账户冻结/解冻、登录日志记录 |
| 4 | **高并发支撑** | 登录接口需支撑峰值 5万 QPS 的认证请求 |
| 5 | **服务内聚** | 用户信息通过 Feign 接口供其他微服务调用，避免各服务重复查询数据库 |

### 1.3 用户角色

| 角色 | 说明 |
| :--- | :--- |
| **普通用户（C端）** | 注册、登录、查看/修改个人信息 |
| **管理员（后台）** | 查看用户列表、冻结/解冻用户（由管理端 Web 调用） |
| **内部服务** | 通过 Feign 接口获取用户信息（无需鉴权，走内部调用） |

### 1.4 模块边界

| 包含内容 | 不包含内容 |
| :--- | :--- |
| 用户注册、登录、登出 | 用户权限管理（RBAC）—— 由独立权限模块负责 |
| JWT 令牌生成与验证 | 第三方登录（微信/支付宝） —— 二期规划 |
| 用户信息查询与修改 | 消息通知（短信/邮件） —— 由通知模块负责 |
| 用户状态管理（冻结/解冻） | 用户积分/等级 —— 由会员模块负责 |
| 登录日志记录 | 支付密码 —— 由支付模块负责 |


## 2. 功能需求

### 2.1 用户注册

| 项目 | 说明 |
| :--- | :--- |
| **功能编号** | UC-001 |
| **功能名称** | 用户注册 |
| **触发条件** | 用户访问注册页面并提交注册信息 |
| **前置条件** | 无 |
| **后置条件** | 系统创建用户账户，返回注册成功信息 |

**输入字段：**

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
| :--- | :--- | :---: | :--- | :--- |
| `username` | String | ✅ | 4-20位字母/数字/下划线，唯一 | 登录用户名 |
| `password` | String | ✅ | 8-20位，至少含字母和数字 | 登录密码 |
| `confirmPassword` | String | ✅ | 必须与 password 一致 | 确认密码 |
| `phone` | String | ✅ | 11位中国大陆手机号，唯一 | 手机号 |
| `email` | String | ❌ | 标准邮箱格式 | 邮箱（选填） |

**业务规则：**

1. 用户名全局唯一，重复则返回错误提示
2. 手机号全局唯一，重复则返回错误提示
3. 密码使用 BCrypt 加密存储，不存储明文
4. 注册成功后自动生成雪花 ID 作为用户ID
5. 新用户默认状态为「正常」（status = 1）

**异常场景：**

| 异常场景 | 错误码 | 错误信息 |
| :--- | :---: | :--- |
| 用户名为空 | 400 | 用户名不能为空 |
| 用户名已存在 | 409 | 用户名已被占用 |
| 手机号已注册 | 409 | 手机号已被注册 |
| 密码长度不足 | 400 | 密码长度需为8-20位 |
| 两次密码不一致 | 400 | 两次密码输入不一致 |
| 手机号格式错误 | 400 | 手机号格式不正确 |


### 2.2 用户登录

| 项目 | 说明 |
| :--- | :--- |
| **功能编号** | UC-002 |
| **功能名称** | 用户登录 |
| **触发条件** | 用户在登录页输入凭证并提交 |
| **前置条件** | 用户已注册 |
| **后置条件** | 系统签发 JWT Token，记录登录日志 |

**输入字段：**

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
| :--- | :--- | :---: | :--- | :--- |
| `username` | String | ✅ | 已存在的用户名 | 可使用用户名或手机号登录 |
| `password` | String | ✅ | 正确的密码 | 登录密码 |

**业务规则：**

1. 支持用户名/手机号两种登录方式
2. 密码校验使用 BCrypt 匹配
3. 登录成功后生成 JWT Token（有效期 2 小时）
4. 登录成功后记录登录时间、登录 IP
5. 同一账号连续登录失败 5 次，锁定 15 分钟（防暴力破解）
6. 被冻结的用户无法登录

**响应信息：**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `token` | String | JWT 访问令牌 |
| `userId` | Long | 用户ID |
| `username` | String | 用户名 |
| `avatar` | String | 头像URL |

**异常场景：**

| 异常场景 | 错误码 | 错误信息 |
| :--- | :---: | :--- |
| 用户名不存在 | 401 | 用户名或密码错误 |
| 密码错误 | 401 | 用户名或密码错误 |
| 账户已冻结 | 403 | 账户已被冻结，请联系管理员 |
| 登录失败次数超限 | 429 | 登录失败次数过多，请15分钟后再试 |
| 请求频率过高 | 429 | 请求过于频繁，请稍后再试 |


### 2.3 用户登出

| 项目 | 说明 |
| :--- | :--- |
| **功能编号** | UC-003 |
| **功能名称** | 用户登出 |
| **触发条件** | 用户点击登出按钮 |
| **前置条件** | 用户已登录 |
| **后置条件** | 客户端清除 Token，服务端无状态无需处理 |

**业务规则：**

1. JWT 无状态认证，登出仅需客户端清除 Token
2. 服务端可记录登出日志（可选）
3. 支持 Token 黑名单机制（如需主动失效），可将 Token 存入 Redis 黑名单

| :--- | :--- |
| **功能编号** | UC-005 |
| **功能名称** | 修改用户信息 |
| **触发条件** | 用户在个人中心编辑信息并保存 |
| **前置条件** | 用户已登录 |
| **后置条件** | 用户信息更新成功 |

### 2.6 修改密码

| 项目 | 说明 |
| :--- | :--- |
| **功能编号** | UC-006 |
| **功能名称** | 修改密码 |
| **触发条件** | 用户主动修改登录密码 |
| **前置条件** | 用户已登录 |
| **后置条件** | 密码修改成功，需重新登录 |

**输入字段：**

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
| :--- | :--- | :---: | :--- | :--- |
| `oldPassword` | String | ✅ | 当前正确密码 | 旧密码 |
| `newPassword` | String | ✅ | 8-20位，含字母和数字 | 新密码 |
| `confirmPassword` | String | ✅ | 必须与 newPassword 一致 | 确认新密码 |

**业务规则：**

1. 旧密码校验使用 BCrypt 匹配
2. 新密码不能与旧密码相同
3. 密码修改成功后，旧 Token 仍有效（但建议前端引导重新登录）

**异常场景：**

| 异常场景 | 错误码 | 错误信息 |
| :--- | :---: | :--- |
| 旧密码错误 | 401 | 旧密码输入错误 |
| 新旧密码相同 | 400 | 新密码不能与旧密码相同 |
| 新密码格式不符 | 400 | 密码需为8-20位，含字母和数字 |

## 3. 非功能需求

### 3.1 性能需求

| 指标 | 目标值 | 说明 |
| :--- | :---: | :--- |
| 注册接口响应时间 | < 500ms | 正常负载下 |
| 登录接口响应时间 | < 200ms | 不含密码加密计算耗时 |
| 登录接口 QPS | ≥ 50000 | 峰值流量 |
| 用户信息查询 QPS | ≥ 100000 | 缓存命中率 ≥ 95% |
| 系统可用性 | 99.99% | 全年停机时间 < 53分钟 |

### 3.2 安全需求

| 需求项 | 说明 |
| :--- | :--- |
| 密码加密 | 使用 BCrypt 加密（强度系数 10） |
| 传输安全 | 全链路 HTTPS（生产环境） |
| 防暴力破解 | 连续 5 次登录失败锁定 15 分钟 |
| 防重放攻击 | JWT 包含过期时间（2小时） |
| 防 Session 伪造 | Token 包含签名，服务端不保存 Session |
| SQL 注入防护 | 使用 MyBatis-Plus 参数绑定 |
| 敏感信息脱敏 | 手机号、邮箱在返回前端时脱敏 |

### 3.3 缓存策略

| 缓存对象 | 缓存方式 | 过期时间 | 说明 |
| :--- | :--- | :---: | :--- |
| 用户信息（单条） | Redis String | 30分钟 | key: `user:info:{userId}` |
| 用户登录记录 | Redis String | 2小时 | key: `user:login:{userId}` |
| 登录失败计数 | Redis String | 15分钟 | key: `user:login:fail:{username}` |

### 3.4 扩展性需求

- 支持后续扩展第三方登录（微信、支付宝）
- 支持后续扩展手机号/邮箱验证码登录
- 用户信息表预留扩展字段（`ext_info` JSON 类型）


## 4. 接口设计

### 4.1 对外 RESTful API

| 接口名称 | 方法 | 路径 | 是否需要认证 |
| :--- | :---: | :--- | :---: |
| 用户注册 | POST | `/api/user/register` | ❌ |
| 用户登录 | POST | `/api/user/login` | ❌ |
| 用户登出 | POST | `/api/user/logout` | ✅ |
| 获取当前用户信息 | GET | `/api/user/info` | ✅ |
| 修改用户信息 | PUT | `/api/user/info` | ✅ |
| 修改密码 | PUT | `/api/user/password` | ✅ |
| 获取用户列表（管理员） | GET | `/api/user/list` | ✅（管理员） |
| 冻结/解冻用户（管理员） | PUT | `/api/user/status` | ✅（管理员） |

### 4.2 内部 Feign 接口

| 接口名称 | 方法 | 路径 | 说明 |
| :--- | :---: | :--- | :--- |
